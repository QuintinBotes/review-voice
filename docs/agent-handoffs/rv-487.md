## Goal and scope

Implement issue #487, follow-ups to #482. #482 added `plugins/review-voice/src/git-exec.ts` with `runGitCatFileSync`, which runs git detached in its own process group, bounds it, and kills the group on timeout.

1. **Remaining unbounded git calls.** Route the git calls in the diff path through the same bounded runner, or a sibling of it in `git-exec.ts`, with a named timeout constant each. A partial clone's lazy fetch can stall these calls:
   - the `cat-file -e` checks in acquisition (`src/diff/pull-request.ts` already passes a 10 s timeout to one of them, but it is not group-killed);
   - `check-attr` (find it with grep);
   - any other `execFileSync('git', ...)` in `src/diff/**` or `src/conventions/**` with no group kill.

   A timeout degrades as each call's failure already does today.
2. **Ctrl-C while blocked.** git now runs detached, so an interrupt that kills node can leave the detached git or ssh running, unbounded. While a bounded git call is in flight, kill its recorded process group on SIGINT or SIGTERM, then let the signal proceed. Keep it synchronous-safe. If that is not achievable for a synchronous `spawnSync` (the signal handler cannot run while node is blocked), say so and document the limit in a `shortcut:` comment instead of inventing machinery. Do not change behaviour.
3. **Windows.** Leave the existing documented shortcut as it is. No job objects.

Add a CHANGELOG entry under Unreleased citing #487. Rebuild `dist`. Do not bump the version.
