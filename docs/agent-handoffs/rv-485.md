## Goal and scope

Implement issue #485: a stored score breakdown records the verifier's verdict and the gate that held it as data, next to the existing `rejectedBecause` prose. Every consumer then reads the field instead of parsing the sentence.

- **New fields on `ScoreBreakdown`** (`plugins/review-voice/src/scoring/score.ts`):
  - `verified: boolean | null` and `premisesVerified: boolean | null`, copied from the verification entry, or null when there is none.
  - `gate: HoldGate | null`. A stable code for the one rule that held the candidate, null when eligible. Define `HoldGate` as a string union covering every rejection branch in `scoreCandidate`. Suggested codes, adjusted to what the code actually has: `duplicate-precedent`, `already-said`, `question-premises-false`, `question-unverified`, `question-gap`, `owner-precedent-question`, `unverifiable`, `verified-false`, `confidence-floor`, `owner-precedent`, `materiality`, `score`, `anchor`, `stale-consumer`, `citation`, `question-cap`.
  - Also set `gate` from every later stage that holds a candidate scoring left eligible, or that rewrites its reason:
    - policy suppression: `policy`;
    - uncorrectable correction: `uncorrectable-correction`;
    - the absence check: `absence`;
    - the echo and citation `Also:` checks;
    - challenge holds: `challenge-partly`, `challenge-refuted`.
- **Readers:**
  - `gateOf` in `src/cli/score.ts` reads `breakdown.gate` when present and keeps today's prose parsing only for old stored breakdowns that have no `gate`.
  - The below-gate mapping in `src/store/runs.ts` reads it the same way.
  - `holdReasonOf` in `score.ts`, if present on this branch, uses `gate`; its materiality bucket must come only from `gate === 'materiality'`.
- **Keep the prose.** `rejectedBecause` is unchanged for people. Nothing that is posted or rendered changes wording.
- **Docs.** Add ADR `docs/adr/0041-holds-are-recorded-as-data.md` (0037 to 0040 are taken by branches in flight), short, citing #485. Add an index row, a CHANGELOG entry under Unreleased, and a note in `docs/ARCHITECTURE.md` where the score breakdown is described. Rebuild `dist`. Do not bump the version.
