## Goal and scope

Issue #477. After a conflicting replay, `interdiffFrom` in `plugins/review-voice/src/diff/incremental.ts` (around lines 981-996) keeps whole hunks for files listed as "mixed" (base and author edits could not be separated) and "whole" (resolution could not be matched to hunks). Those hunks can carry `+` lines that the base branch brought in through a merge, which are not changed lines of the pull request's own diff (merge base to head). check-candidates then accepts an anchor on such a line and posting fails (GitHub 422: the line is not in the PR diff).

Fix: for every file whose interdiff text came from that conflicting-replay path (the `fresh.text` pushed into `resolved`), demote each `+` line whose head-side line number is NOT a `+` line of that file's own diff (`own.get(path)`, the merge-base-to-head section already read) to a context line (`' '` prefix), and correct the hunk header counts (a demoted line now counts on the old side as well). Drop a hunk that is left with no `+` and no `-` lines. If a file's section ends up with no hunks, leave it out of the patch. Keep `-` lines as they are. Add a note to `detail` naming the files where base lines were demoted, e.g. `shown as context where the base added lines after a conflicting replay: <paths>`.
